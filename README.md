# 포켓몬 데이즈

가로 16:9 PC 화면을 기준으로 제작한 한국어 방치형 RPG 1차 프로토타입. 좁은 화면에서는 반응형으로 재배치합니다. Vite + JavaScript ES 모듈이며 백엔드 없이 실행합니다.

## 실행

Node.js 20.19+ 또는 22.12+가 필요합니다. 현재 환경은 Node.js 24입니다.

```sh
cd /workspace/digimon-AFK
npm ci
npm run dev -- --port 5173
```

```sh
npm test           # 전투, 보스, 소환, 성장, 편성, 저장 검증
npm run test:e2e  # Chromium 브라우저에서 실제 UI 흐름 검증
npm run build     # 배포용 dist 생성
npm run preview   # 빌드 결과 확인
```

## 구현 범위

- 6마리 파티, HP와 공격력, 자동 공격·반격·치명타 시각 효과, 1/2/3배속.
- 일반 적 10마리 처치 후 수동 또는 자동 보스 도전. 처치 골드, 보스 다이아 100개, 다음 스테이지 자동 이동.
- 보스전 60턴 제한 또는 전멸 시 파티 회복 후 현재 스테이지 일반 사냥 복귀. 반복 실패를 막기 위해 자동 보스 도전 해제.
- 지역당 20개 스테이지. 지역별 배경 색상과 이름 변경. 첫 4지역 이후 배경 이름은 순환하고 난이도는 계속 증가.
- 1회 300 / 10회 2,700 다이아 소환. 일반 50%, 고급 28%, 희귀 15%, 영웅 6%, 전설 1%. 등급 내 균등 확률. 중복은 개별 개체로 보관. 별도 천장 없음.
- 등급/전투력 정렬, 상세 보기, 골드 레벨업(최대 100), 최소 1~최대 6마리 편성.
- 초기 지급: 골드 2,400, 다이아 3,600, 기본 파티 6마리. 최초 10마리 처치 퀘스트 보상 300 다이아.
- localStorage에 스테이지, 재화, 보유 개체, 레벨, 편성, 설정 자동 저장. 보상·편성·성장 즉시 저장. 새로고침 시 복원.

## 사용자 도트 이미지 연결

이미지를 생성하거나 외부 포켓몬 이미지를 다운로드하지 않습니다. 이미지가 없으면 몬스터볼 모양의 일반 UI 플레이스홀더를 표시합니다.

`public/pokemon/<전국도감번호>.png`에 사용자 제공 파일을 넣으세요. 예: `1.png` 이상해씨, `4.png` 파이리, `7.png` 꼬부기, `25.png` 피카츄. 다른 파일 경로는 `src/data.js`의 `sprite` 필드로 지정할 수 있습니다. CSS `object-fit: contain`과 `image-rendering: pixelated`로 원본 비율·픽셀을 유지합니다.

데이터는 PokeAPI의 전국도감 번호 체계와 호환되는 로컬 목록입니다. 실시간 PokeAPI 의존성은 없으며 능력치·등급·확률은 이 프로토타입의 자체 밸런스입니다. 새 포켓몬은 `SPECIES`에 데이터를 추가하면 목록·소환 풀에 반영됩니다.

## 파일 구조

- `src/data.js`: 포켓몬, 등급, 이미지 경로, 지역 정의
- `src/game.js`: UI와 독립된 상태·전투·소환·저장 로직
- `src/main.js`: 화면, 모달, 이벤트, 전투 연출
- `src/style.css`: 반응형 UI와 애니메이션
- `tests/game.test.js`: Node 기본 테스트 러너 기반 회귀 테스트
- `tests/browser/game.spec.js`: Playwright 브라우저 회귀 테스트 (`CHROMIUM_PATH`로 브라우저 경로 지정 가능, 기본 `/usr/bin/chromium`)

## 현재 제한

서버 저장, 계정, 오프라인 누적 보상, 사운드, 스킬·시너지, 결제는 포함하지 않습니다. 숨겨진 탭에서는 전투를 멈추며 복귀하면 재개합니다. 브라우저 저장소 삭제 시 데이터가 사라집니다. 전투 중 적 HP는 저장하지 않아 새로고침 시 같은 스테이지에서 새 적으로 재시작합니다. 로컬 데이터 수정 방지나 여러 탭 동시 실행의 상태 병합은 제공하지 않습니다. 기본 UI 글꼴은 Google Fonts를 시도하고 연결되지 않으면 시스템 한글 글꼴로 대체됩니다.

클라우드 작업은 이미 격리되어 있으므로 기존 체크아웃을 사용하세요. 사용자가 요청하지 않는 한 별도 Git worktree를 생성할 필요가 없습니다. 설치 파일은 유지되지만 개발 서버 프로세스는 새 세션에서 위 명령으로 다시 시작해야 합니다.
